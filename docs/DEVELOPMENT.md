# 开发规范

本文规定新增实现应满足的要求，不表示相关代码、工具或功能已经存在。项目范围见 [README](../README.md)，协作流程见 [贡献指南](../CONTRIBUTING.md)。

## 1. 版本与依赖

- 初期固定 Minecraft Java 1.21.1、Java 21，分别适配 Fabric 和 Minecraft Forge；不得以 NeoForge 替代 Forge 验收。
- 工程任务需锁定 Gradle Wrapper、加载器、映射、Fabric API 及其他依赖版本。避免动态版本、未审查快照和不必要的工具链升级。
- 使用仓库 Wrapper，构建命令由工程 PR 实测后写入文档；当前无 Wrapper，不能声称可以构建。
- 新依赖记录官方来源、固定版本、许可证、用途、目标版本兼容性及替代方案。涉及架构的选择写入 [ADR](decisions/0000-template.md)。
- 不通过系统批量升级解决依赖问题；不在项目脚本中安装或升级内核、显卡驱动。个人机器安装软件需得到机主授权并核对依赖变更。

## 2. 模块边界与代码风格

公共核心承担模型协议、会话、人设、任务状态与规则，不依赖加载器、客户端类或具体世界实现。加载器适配层处理注册、事件、网络、玩家实体和世界操作。具体模块名称待工程验证，不提前绑定框架。

Java 使用 UTF-8、4 空格缩进、禁止通配符导入；类型用 `UpperCamelCase`，方法和字段用 `lowerCamelCase`，常量用 `UPPER_SNAKE_CASE`。包名使用小写，最终根包名由工程任务确定。

保持方法职责清晰；注释解释约束和原因，避免复述代码。对外接口说明线程、生命周期、可空性、失败与取消语义。不吞异常、不以 `null` 或无意义默认值伪装成功；对边界输入返回可辨认的错误。格式化工具选定后提交配置，避免顺手改写无关文件。

文档与日志以中文说明为主，代码标识符采用清楚的英文。公共接口变更在同一 PR 更新调用方、适配层与文档。

## 3. 线程、异步与生命周期

- 模型 HTTP、重试与耗时处理离开游戏 tick 线程；禁止在 tick 中使用阻塞网络、休眠或同步等待异步结果。
- 读取世界形成快照及修改世界均遵守对应端的线程约束。异步推理只使用快照，不持有可变世界对象跨线程操作。
- 模型回传意图经游戏线程重新校验后执行；校验世界会话、玩家、伙伴、任务 ID 及取消代次，丢弃旧世界和旧任务结果。
- 世界卸载、断线和伙伴移除时取消请求与任务，释放资源；取消后不触发补发动作，不清理到别的玩家任务。
- 网络请求、上下文、队列、寻路和感知均有上限与超时；记录预算和超限行为，禁止无限重试和无界缓存。

## 4. 模型、动作与权限

模型负责表达意图，游戏规则决定是否执行。初期采用有类型的结构化动作，不执行模型输出的任意 Lua/Java、系统命令或服务器管理命令。

每个动作至少约定：参数类型与范围、执行者/目标身份、前置条件、超时与取消、成功结果及失败原因。服务端校验归属、距离、维度、区块状态、物品数量和权限；客户端包与模型输出都不能直接授权世界修改。

任务状态至少覆盖 `QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED`、`TIMED_OUT`、`CANCELLED`；规划阶段单独记录，不提前认定已执行。状态变化由执行器确认，终态不可被迟到回复改回运行状态。重试必须防止重复挖掘、扣物品和交付。

停止请求优先处理，清除当前任务产生的移动/交互输入；具体生效时间以游戏 tick 和停止验收记录为准。任务取消不能伪装为完成。

挖掘、拾取、背包和交付遵守生存模式规则，不生成资源作弊，不绕过服务端事件取消。破坏性修改仅在用户已指定或确认的任务范围内进行；是否兼容某领地模组必须以实际适配与测试为依据。

## 5. 会话与记忆

- 使用稳定玩家 UUID、世界标识及伙伴 ID 隔离状态，不仅依赖可改名的显示名称。
- 对话排序、取消、长度和上下文预算必须明确；不默认收集全服聊天。
- 长期记忆记录来源，区分用户明确偏好、已发生事件和模型推测。被取消的任务不能写为已完成事件。
- 支持查看、删除与清空。清空后移除持久化内容、检索索引和内存缓存，并防止在途旧请求重新写回；备份保留规则需公开。
- 主动回应设冷却和可关闭配置；保持 AI 身份，避免刷屏或用内疚、威胁、排他表达要求用户继续游玩。

## 6. 配置与默认行为

新增一般功能、诊断及不改变控制权的观察接口默认开启，并在配置文档记录默认值。这个约定不允许恢复所有历史实验，也不允许绕过任务授权、权限校验或费用配置。

没有用户提供的模型配置时启用不联网的 Mock/未配置状态，不偷偷使用内置密钥、选择付费服务或自动发送请求。主动发言即便启用也要遵守冷却；遥测与上传私人聊天不属于默认诊断。

每个真实配置项必须记录：键名、所在端及文件路径、类型、默认值、允许范围、是否需要重启/重载，以及隐私和费用影响。无效值有可读错误，不能静默放宽权限。当前尚无配置格式，不在文档中捏造可用路径或命令。

## 7. 数据、网络与日志

模型凭据仅保存在明确选定的受信任调用端，不广播给其他客户端；在哪一端推理由 ADR 决定。允许用户配置服务地址，同时明示上下文将发送给该服务；不无故引入项目中转服务器。

网络消息校验发送者、大小、类型、频率和参数，避免客户端伪造归属或重放动作。持久化需有 schema 版本、异常恢复及原子写入方案；涉及物品恢复尤其要防止复制和回滚错误。

日志记录任务 ID、状态、耗时、错误分类和脱敏后的必要上下文。禁止默认输出完整请求/响应、聊天、授权头和密钥，也不能在崩溃信息中泄漏它们。调试采样和日志缓存有大小与保留上限。

测试世界、账号数据、密钥、真实聊天、构建缓存和生成产物不提交仓库；工程建立时补全相应 `.gitignore`。

## 8. 验证与交付

按 [测试规范](TESTING.md) 选择与风险相称的检查。协议校验、任务取消、会话隔离和重复执行等逻辑应有有意义的自动化测试；纯文档和低影响可逆修改不为凑数量写测试。

每次交付同时更新实际行为、配置和限制说明。文档区分“已实现”“已验证”“规划中”，双加载器构建成功不等于四种运行环境均通过。没有执行的检查标注“未测试”并说明原因。
