# 架构草案

状态：**总体架构草案，尚非完整实现**。玩家控制路线已按 [ADR 0001](decisions/0001-player-control-route.md) 接受，依据为独立基础探针；其余模块仍需实现和验证。本文用于对齐并行开发边界，最终实现以 ADR 和实测结果为准。前置任务：[玩家控制验证 #1](https://github.com/Y-fyan/minecraft-friends/issues/1)、[双加载器工程 #2](https://github.com/Y-fyan/minecraft-friends/issues/2)。

## 设计目标

以单玩家拥有一个伙伴为 MVP，围绕聊天、记忆、跟随和采集交付建立闭环。共享业务规则，分别适配 Fabric / Forge 1.21.1；专用服务器保持世界操作的最终授权。单机内置服务器也遵守逻辑端边界。

## 建议分层

| 层 | 职责 | 边界 |
| --- | --- | --- |
| 游戏入口与展示 | 聊天寻址、伙伴显示、简洁状态、配置入口 | 不把普通聊天或其他模组命令误发给 AI |
| 会话与陪伴 | 会话隔离、人格、上下文、记忆和事件回应 | 不越过预算读取私人/全服信息 |
| 模型适配 | 请求、响应解析、取消、超时和 Mock | 异步工作，不直接访问可变世界 |
| 任务核心 | 结构化意图、动作校验、调度、状态与结果 | 不执行任意模型代码，成功由执行结果决定 |
| 加载器适配 | 注册、事件、网络、玩家生命周期、感知与动作 | 世界操作回到正确线程并由服务端校验 |

工程可考虑公共核心加 Fabric/Forge 适配模块。是否使用额外的多加载器框架、如何处理映射差异，需用最小构建验证后决定；本草案不绑定具体目录或依赖。

## 一次任务的数据流

1. 用户在聊天框寻址伙伴。入口识别发送者、伙伴与会话，普通聊天保持原有行为。
2. 在游戏允许的线程获取范围有限的快照，与当前会话和必要记忆组合成模型输入。
3. 推理端异步请求用户配置的模型服务；等待时游戏仍正常 tick。
4. 解析模型的聊天回复或任务意图，拒绝未知动作、非法数量和无权限目标。
5. 执行端核对世界会话、主人与任务代次，经服务端校验后在游戏线程执行。
6. 执行器产生真实结果，更新任务状态，再生成聊天反馈及必要的事件记忆。

取消、世界卸载或断线会使对应上下文失效。迟到的模型结果和重试请求都不能恢复已取消任务。推理部署在客户端还是服务端尚待决策；若跨端传意图，只传必要结构化数据，不把服务凭据附在执行消息中。

## 接口约定方向

以下是契约建议，不是已存在的 Java 类型：

| 契约 | 最少需要说明的内容 |
| --- | --- |
| 模型服务 | 输入上下文、请求 ID、超时、取消、类型化结果和错误 |
| 伙伴生命周期 | 身份/归属、创建移除、死亡重生、持久化及重复请求处理 |
| 世界感知 | 快照范围、生成线程、时效、体积预算和不可见信息边界 |
| 动作执行 | 动作 schema、权限、游戏线程、结果、停止和超时 |
| 任务调度 | 任务 ID、队列与状态、优先停止、终态和去重 |
| 记忆存储 | 世界/玩家/伙伴键、来源、版本、删除及旧写入失效 |

依赖这些接口的成员先在 Issue 或 Draft PR 中对齐输入输出，附至少一个成功与失败示例，再分别实现加载器适配和上层调用。

## 必须先解决的决策

| 问题 | 验证要求 | 关联任务 |
| --- | --- | --- |
| 服务器玩家实体还是完整登录客户端 | 玩家身份、背包、移动、挖掘、死亡、玩家列表、认证与皮肤差异；两个加载器分别验证 | #1 |
| 推理所在端和安装矩阵 | 单机/联机消息流、密钥位置、多人隔离、断线后的任务归属 | #1、#5、#6 |
| 公共模块与映射策略 | 两种 JAR 构建及专用服务器启动，不能只验证 IDE 编译 | #2 |
| 导航实现与依赖 | 地表/台阶/障碍、卡住超时、停止，以及依赖版本和许可 | #9 |
| 配置与存储格式 | 校验、迁移、原子写入、删除与损坏恢复 | #4、#5、#7 |

ADR 使用 [模板](decisions/0000-template.md)，以递增编号保存到本目录的 `decisions/` 下。记录证据、备选方案和接受者；草案不能写成已接受决策。改变已接受方案时新增替代记录，保留历史理由。
