# 架构草案

状态：**M0 双加载器骨架已实现；伙伴和游戏玩法仍为提案**。公共配置、模型契约、任务状态和最小加载器入口已通过本地构建与专服初始化验证。玩家控制路线已按 [ADR 0001](decisions/0001-player-control-route.md) 接受，依据为 [独立基础探针](validation/0002-player-control-reproduction.md)；其余模块仍需实现和验证。

当前模块为 `common`、`fabric`、`forge`。两个发行 JAR 把同一份公共源码编入各自产物，避免玩家额外安装公共 JAR；决策见 [ADR 0002](decisions/0002-multiloader-layout.md)。

## 设计目标

以单玩家拥有一个伙伴为 MVP，围绕聊天、记忆、跟随和采集交付建立闭环。共享业务规则，分别适配 Fabric / Forge 1.21.1；专用服务器保持世界操作的最终授权。单机内置服务器也遵守逻辑端边界。

## 建议分层

| 层 | 职责 | 边界 |
| --- | --- | --- |
| 游戏入口与展示 | 聊天寻址、伙伴显示、简洁状态、配置入口 | 不把普通聊天或其他模组命令误发给 AI |
| 会话与陪伴 | 会话隔离、人格、上下文、记忆和事件回应 | 不越过预算读取私人/全服信息 |
| 模型适配 | 请求、响应解析、取消、超时和 Mock | 异步工作，不直接访问可变世界 |
| 任务核心 | 结构化意图、动作校验、调度、状态与结果 | 不执行任意模型代码，成功由执行结果决定 |
| 加载器适配 | 注册、事件、网络、玩家生命周期、感知与动作 | 世界操作回到正确线程并由服务端校验 |

当前不引入额外的多加载器框架。公共层只包含与加载器无关的配置、模型协议、Mock 和任务状态；游戏事件、网络、世界访问与动作执行仍分别适配。后续公共接口扩大前需提供成功与失败示例并重新评估依赖。

## 一次任务的数据流

1. 用户在聊天框寻址伙伴。入口识别发送者、伙伴与会话，普通聊天保持原有行为。
2. 在游戏允许的线程获取范围有限的快照，与当前会话和必要记忆组合成模型输入。
3. 推理端异步请求用户配置的模型服务；等待时游戏仍正常 tick。
4. 解析模型的聊天回复或任务意图，拒绝未知动作、非法数量和无权限目标。
5. 执行端核对世界会话、主人与任务代次，经服务端校验后在游戏线程执行。
6. 执行器产生真实结果，更新任务状态，再生成聊天反馈及必要的事件记忆。

取消、世界卸载或断线会使对应上下文失效。迟到的模型结果和重试请求都不能恢复已取消任务。ADR 0001 已接受 MVP 在服务端异步推理；若未来跨端传意图，只传必要结构化数据，不把服务凭据附在执行消息中。

## 接口约定方向

以下方向中，`ModelProvider`、`ModelRequest`、`TaskStateMachine`、`ModConfig` 和最小 `LoaderAdapter` 已存在；其余仍是设计目标：

| 契约 | 最少需要说明的内容 |
| --- | --- |
| 模型服务 | 输入上下文、请求 ID、超时、取消、类型化结果和错误 |
| 伙伴生命周期 | 身份/归属、创建移除、死亡重生、持久化及重复请求处理 |
| 世界感知 | 快照范围、生成线程、时效、体积预算和不可见信息边界 |
| 动作执行 | 动作 schema、权限、游戏线程、结果、停止和超时 |
| 任务调度 | 任务 ID、队列与状态、优先停止、终态和去重 |
| 记忆存储 | 世界/玩家/伙伴键、来源、版本、删除及旧写入失效 |

依赖这些接口的成员先在 Issue 或 Draft PR 中对齐输入输出，附至少一个成功与失败示例，再分别实现加载器适配和上层调用。
