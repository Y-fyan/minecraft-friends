# 能力接口与安全执行层

状态：**已实现并通过公共层单测与 Fabric 编译**；真实客户端与 Forge 运行验收见文末的未验证项。本文描述 #28 引入的能力注册表、调用协议与执行边界。

模型只能从注册表里选择已实现的能力，不能写 Java、Lua、脚本或服务器命令。注册能力不等于授权执行：世界操作仍由服务端在提交前和逐 tick 执行中复核。

## 注册表

| 能力 | 参数 | 权限 | 额外授权 | 实际执行 |
| --- | --- | --- | --- | --- |
| `observe` | 无 | 只读 | 无 | 读取有界观测快照；不改变世界 |
| `follow` | 无 | 世界写 | 无 | 现有正常实体跟随 |
| `wait` | 无 | 世界写 | 无 | 停止动作并等待 |
| `stop` | 无 | 世界写 | 无 | 优先取消并清除输入 |
| `collect_oak_logs` | `count` 1–64 | 世界写 | 一次性采集区域 | 现有生存模式采集、拾取与交付 |

不在表中的能力（装备、放置、种地、建造等）尚未实现，因此**不注册**；模型调用会得到 `UNKNOWN_CAPABILITY`，而不是“看起来成功”。新增能力必须先有执行器、服务端复核和验收证据，再进入注册表。

注册表在 `CapabilityRegistry.BUILTIN`，Fabric、Forge、模型提示和 `/mf task capabilities` 使用同一份定义。能力沿用现有全局开关与 Provider 配置（`enabled`、聊天/Provider 开关、超时与上下文预算），**没有新增默认关闭的能力开关**；关闭全局功能时命令与执行同时拒绝。

## 调用协议

模型响应必须是恰好一个 JSON 对象：

```json
{"capability":"collect_oak_logs","arguments":{"count":8}}
```

- 无参数能力可以省略 `arguments`，也可以给空对象。
- 不接受额外顶层字段、额外参数、重复字段、重复参数、数组、`null`、布尔值、字符串数字、小数或溢出整数。
- 上限 1024 字符；超过直接拒绝。
- 未知能力、参数类型错误、越界数值分别返回 `UNKNOWN_CAPABILITY`、`BAD_ARGUMENT`、`OUT_OF_RANGE`；语法或结构错误返回 `BAD_JSON`。
- 普通聊天回复与能力请求严格分开：只有显式规划入口解析能力 JSON，聊天文本永远不会被当成动作。

当前**不使用服务商原生 `tool_calls`**。M3 未实现相应官方协议适配与测试，因此不声称支持。

## 授权与复核

能力只是“候选请求”。执行前在服务器线程重新检查：

1. 规划代次、服务器世界会话、在线主人与伙伴是否仍是同一实例。
2. 主人/伙伴存活、同维度、48 格内、伙伴归属、配置开关与 Provider 可用性。
3. 快照不超过 600 tick；能力仍在注册表中。
4. 需要区域的能力必须与当前一次性授权完全一致：有效期、维度、边界、区块已加载、双方 32 格内。
5. 区域授权在该次采集提交时消费；旧调用、重复调用和迟到回包不能恢复动作。

执行沿用 M2 的有界队列、超时、取消、任务 ID 去重和生命周期清理：停止、断线、伙伴死亡、换维度、世界卸载、Provider/服务器关闭都会使旧请求失效。

## 结果关联

服务器为每次调用分配 call id（等于规划请求 ID），并复用为任务 ID：

- `/mf task status` 显示规划状态、任务状态和 `能力 … / 调用 … / 状态 / 已完成 / 已交付 / 结果说明`。
- 只读 API `ActionRuntime.capabilityResult(MinecraftServer, UUID)` 返回不可变 `CapabilityResult`，可在服务器线程轮询。
- `/mf task capabilities` 列出注册表；不创建任务、不改变世界。
- 计数、交付数和终态只来自执行器；模型文本不能写入成功状态。
- `observe` 没有任务，`taskId` 为全零 UUID，状态由服务端读取结果决定。

## 预算与限制

| 限制 | 值 |
| --- | --- |
| 单次调用 JSON | 1024 字符 |
| 每次规划的能力数 | 1 |
| 单次规划指令 | 512 字符 |
| 规划超时 | 现有 `requestTimeoutSeconds`，最多 30 秒 |
| 规划并发 | 全局 16，每位主人 20 tick 一次 |
| 快照年龄 | 600 tick |
| 采集数量 | 1–64 |
| 观测方块 | 伙伴周围最多 245 个位置、64 个非空气方块 |
| 观测库存 | 伙伴自身最多 41 个槽位；不读取其他玩家背包 |

`observe` 的结果回给主人，但当前一次性规划不会再发起第二轮模型调用；把观测结果用于后续决策属于 #29 的多步任务范围。

## 不支持与未验证

- 不执行模型给出的代码、命令、坐标、`/give`、`/fill`、直接方块批改或传送。
- 不支持原生 `tool_calls`、多步能力链、装备/放置/种地/建造能力。
- 本 PR 只运行了 `:common:test`（97 项）与 `:fabric:compileJava`；**Forge 编译与真实客户端验收未在本机完成**，不得据本文宣称已通过四格矩阵或真实世界执行。
