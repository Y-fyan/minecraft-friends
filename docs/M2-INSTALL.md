# M2 开发构建：安装与首次试用

当前是 PR #26 的开发候选，尚未宣布完整 Alpha 发布。先备份整个存档，再在独立测试世界试用。伙伴会真实改变方块，卸载模组不会自动撤销已经发生的采集。

## 安装

使用 Minecraft Java 1.21.1 与 Java 21。已测试的环境是 Fabric Loader 0.20.1 / Fabric API 0.116.17+1.21.1，或 Minecraft Forge 52.1.20；Forge 不等于 NeoForge。

从本分支运行 `./gradlew checkAll --no-daemon`，或下载对应提交 CI 的构建产物。两个 JAR 位于 `build/artifacts/`：

- Fabric：`minecraft-friends-fabric-1.21.1-0.1.0-SNAPSHOT.jar`，另装上述 Fabric API。
- Forge：`minecraft-friends-forge-1.21.1-0.1.0-SNAPSHOT.jar`。

选择一个加载器，客户端与专服按已验证方式使用相同版本。不要把两个版本混装，也不要安装 experiments 的验收助手；助手会布置测试地图，不用于普通世界。普通专服按加载器官方方法安装，并由服主自己接受 Minecraft EULA。独立安装与启动基础见 [BUILD.md](BUILD.md)。

首次启动生成 `config/minecraft-friends.properties`，默认开启一般功能并使用明确标注的离线演示模型。固定任务指令可离线执行；真实聊天与显式模型规划需要按 [MODEL.md](MODEL.md) 配置用户自己的服务和环境变量凭据。没有内置或随模组分发的密钥。启动游戏/专服的进程必须继承该环境变量，不把密钥贴入 properties、命令参数或 Issue。

## 首次流程与短演示

在自己的测试世界中输入：

```text
/mf companion create MF_Friend
@MF_Friend 跟着我
@MF_Friend 在这里等我
/mf task area x1 y1 z1 x2 y2 z2
@MF_Friend 帮我收集 8 个橡木原木并交给我
/mf task status
/mf task stop
```

区域坐标必须选自己确认允许采集的橡木区域，不能照抄固定验收地图的坐标。区域内的橡木建筑柱子也会被当作原木，因此不要把建筑选进去。区域有距离、体积、区块加载及服务端权限限制；一次授权只用于一次任务，失败重试要重新选区。任务不会默认扫描并拆除附近房屋。

实测流程为：主人发送指令 → 伙伴正常移动 → 按生存耗时挖掘 → 等待原版掉落与实际拾取 → 走回主人近距离交付。确认成功要看实际库存和任务状态，模型说“可以帮忙”不等于任务已经完成。

固定中文采集句支持明确的1–64数量。更一般的明确请求使用 `/mf task plan <自然语言>`；只有配置好模型后，它才会后台请求严格任务 JSON，再由服务端复验和执行。普通聊天不会任意执行模型回复；不支持脚本、服务器 OP 命令或任意物品挖掘。

`/mf task stop` 和 `/mf task clear` 直接停止当前动作与规划，不等模型返回。取消/失败时按实际数量反馈；已拾取但无法交付的物品保留在伙伴背包，不隔空转移给主人。`/mf task status` 中成功表示执行器确认完成，失败/超时/取消都不能当成功。

跟随默认约3格，地表寻路有半径和节点预算。高级距离设置在游戏/专服 JVM 参数中使用 `-Dminecraftfriends.actions.follow-distance=3`，范围2–8；不是 properties 或 Gradle 参数。开木门需要伙伴有空热键栏位，受保护或拒绝交互的门会安全失败；不承诺复杂洞穴、跨维度自动追随或所有领地插件兼容。

## 卸载与数据

先停止任务并 `/mf companion dismiss`，关闭游戏/专服后备份整个世界，再移除所选加载器的模组 JAR。不会自动把伙伴全部物品交还给主人；保留原始世界数据和备份，需要时装回相同版本并召回伙伴。不要把删除数据文件当作卸载步骤。

## 验收边界

实际四格任务流程、双玩家隔离和失败用例均有逐项证据，但不是所有整合包、所有模型或长期体验保证。M2 规划的游戏内网络测试使用本机协议模拟器，不冒充真实语言模型。最终发布还需核对性能对照、安装试走及兼容声明；目前没有创建版本标签或 Release。
