# 有界普通树伐木技能（#31，执行器阶段）

**已实现，但本轮未编译/运行游戏适配层。** 这是基于 M2 的独立树木执行技能，不是 #28 的能力注册表，也不是 #29 的普通聊天任务理解。使用显式命令和有类型服务端 API；没有把“帮我砍树”等关键词冒充自然聊天端到端验收。#31 的聊天验收仍依赖 #28、#29，PR 应使用 `Refs #31`，不能提前关闭。

## 使用方式

默认随已有 `enabled=true` 可用，无新配置项，无模型请求或费用。伙伴必须生存、在线、存活且属于当前主人。先给伙伴实际可用的斧头；若希望补种，伙伴主背包中需有相应橡树/白桦树苗。执行器可以选择快捷栏中的工具，或交换主背包的真实物品来装备；不会生成斧头/树苗。

```text
/mf task area 10 64 10 10 71 10
/mf task tree preview 10 64 10
# 核对返回的树种、精确原木坐标和一次性编号，再执行：
/mf task tree confirm <本次预览编号>
# 如不希望补种，显式传 false：
/mf task tree confirm <本次预览编号> false
/mf task status
/mf task stop
```

坐标仅为示例，须替换为实际树干底部和包含整根树干的选区。区域沿用 M2 上限（4096 格、主人和伙伴均在各角点 32 格内、已加载、世界边界内）；`preview` 不会修改方块。每位主人每 20 tick 最多预览一次，预览最多有效 30 秒，且不能超过选区的五分钟有效期。重新选区/预览、停止、暂离、死亡、断线、换维度或服务器停止使旧预览失效。确认绑定当前主人、伙伴**实体实例**、维度和观测状态，重复确认不会停止/重启当前任务，也不会重复交付。

选区在本技能中不是“里面所有原木都可拆”的授权。每次只确认一棵候选树的精确 4–8 个竖直原木，树旁原木不会因处于包围盒中被加入目标；没有自动扩张到相邻树或建筑。当前不提供一条命令批量砍整片树林。

## 识别和到达边界

- 支持普通直干橡树、白桦，映射各自原木/树叶/树苗。不支持巨型树、分叉大橡树、树屋或复杂形状。
- 围绕用户选定基部观察 x/z ±3、y −1..10，最多 588 个方块；不会加载未知区块。要求基部在土壤上、连续 4–8 格竖直同种原木、足够且分布合理的非持久同种树冠。
- 额外原木、其他结构、横向原木、持久树叶、混合或越界树冠、未加载观测都会拒绝并说明原因。宁可拒绝相邻/斜坡/密集树，也不猜测建筑可拆。
- **树形是保守启发式，不证明自然来源。** 人工仿造天然树仍可能通过，所以始终先展示精确目标并要求主人确认。附近木屋导致拒绝时，缩小授权区也不能绕过周边观测；请选择独立的受支持目标。
- 确认前复核完整观测；执行时复核剩余目标状态，并在接近目标及每次完成挖掘前复核原观测，允许原树叶正常衰减/距离更新，不允许新增连接结构。相同状态的替换没有来源历史可供识别。
- 只使用已有地表寻路、正常 `travel`、原版生存挖掘，逐次检查视线、交互距离、归属/区块、工具和保护权限。仅在原基部附近地面寻找站立位置，不远程删除、不飞行/传送/搭垫块、不强制清叶。高处或遮挡原木不可达时停止，保留未完成数并尝试交付已经实际拾取的物品。

预算：每个动作 tick 沿用最多 8 个主人、4 次 A*（每次 512 节点）、2 次目标选择扫描。树木还有每次接近/完成挖掘最多 588 格的结构复核、每次到达候选最多 147 个附近站立格的检查，**不包含在两次区域扫描计数内**；预览单次最多 588 格并有冷却。伐木阶段最多五分钟服务器 tick；每块掉落等待最多十秒、补种最多十秒、返回交付最多一分钟。树任务使用实际服务器 tick 差，而非轮转服务次数，兼容有符号 tick 回绕。未进行游戏性能测量，不能宣称性能验收通过。

## 真实物资与结果

`/mf task status` 同时显示树任务 ID、状态、计划/已砍/已收/已交和补种结果：

- **已砍**：本任务的生存挖掘调用后方块实际消失；不是请求数量。
- **已收**：本任务新产生且可归属的原木实体被伙伴通过正常拾取获得；不是附近地上原木数或背包总数。
- **已交**：主人在同维度、存活、归属仍有效、伙伴三格以内时，实际进入主人可兼容库存槽的数量。交付只做一次，不补发资源；满背包剩余物品留在伙伴。
- `SUCCEEDED` 表示所有计划原木已砍、已收、已交。缺工具、事件拒绝、背包满、树已改变、未拾到或高处不可达会明确失败/部分数量；取消保留已发生数量，不能改报成功。

归属采取保守策略：在每次潜在破坏调用**紧前**采样掉落，只跟踪新出现的单原木实体 UUID。旧堆栈增长、掉落合并、无法证明来源、他人拿走或丢失均不推断为任务拾取。原木发生合并时，即使伙伴实际捡到相关物品，也可能未获本任务记账/交付；结果会不完整，物品仍在真实背包或世界中，不生成补偿。原 M2 橡木采集保留既有合并处理，未将本技能的严格记账宣称为 M2 全路径已修复。

完整树干处理后默认尝试一次补种：原基部必须为空、原土壤未变、原版树苗可存活且可正常接近，使用匹配树种的**真实树苗**通过 `gameMode.useItemOn` 放置。只有实际出现匹配树苗且实际物品减少一个才记 `PLANTED`；不直接写方块，不强制叶子掉落或催长，不失败重试扣苗。没有树苗不等待叶子掉落，也不扩大采集范围。部分树干留下时不补种。

| 补种结果 | 含义 |
| --- | --- |
| `PENDING` | 尚未处理；不是成功 |
| `PLANTED` | 原版交互后观察到树苗和实际消耗 |
| `NO_SAPLING` | 没有匹配的真实树苗；未生成 |
| `BLOCKED` | 位置/土壤/生存规则改变，保护拒绝或实际放置/消耗未确认 |
| `UNREACHABLE` | 无法正常靠近、补种路径受阻或超时 |
| `PARTIAL_TREE` | 留下未砍原木，未尝试补种 |
| `DISABLED` | 用户传 `false` |
| `CANCELLED` | 补种前任务已取消 |

补种为有库存及条件才执行的可选步骤，`SUCCEEDED + NO_SAPLING` 表示伐木交付完成但没有补种，不应转述为“已补种”。

## 服务端接口

仅服务器线程，`previewTree` / `confirmTree` 验证真实在线主人，拒绝后台访问世界；`treeStatus` 也要求服务器线程。调用方不应缓存可变世界或自行构造授权。未来 #28/#29 可适配这些入口，但本 PR 不另建或复制注册表。

```java
ActionRuntime.TreePreview preview = ActionRuntime.previewTree(owner, new TreePosition(x, y, z));
// 展示 preview.plan().logs() 给主人，获得本次明确确认之后：
ActionRuntime.confirmTree(owner, preview.selectionId(), taskId, true);
Optional<TreeTaskStatus> result = ActionRuntime.treeStatus(server, owner.getUUID());
```

纯核心 `TreePlan` 强制精确唯一、底到顶、全部在选区中的 4–8 格树干；`ActionRequest.fellTree` 的区域/数量必须与计划一致。旧模型 `ActionPlan` 不接受 `FELL_TREE`，普通模型文本不能绕过预览确认。任务 ID 去重沿用调度器有界最近 256 条记录；一次性预览另行消费。已有 `stop` / `clear` / 精确本地停止短语不等待模型；两个加载器新增实际死亡/换维度失效钩子，暂离也立即取消。
