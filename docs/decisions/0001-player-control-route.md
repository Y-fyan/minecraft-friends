# ADR 0001：MVP 采用服务端玩家实体控制伙伴

- 状态：**已接受，限初期玩家控制路线与基础可行性**
- 日期：2026-10-25
- 关联任务：[#1](https://github.com/Y-fyan/minecraft-friends/issues/1)
- 提议人：Hgit-1；原提案与实验报告见 [PR #15](https://github.com/Y-fyan/minecraft-friends/pull/15)。
- 文档审查、补充实现与接受者：Y-fyan 账号下的统筹助手，依据创作者“自行决定”及“未完成的你来补全”授权；不表示已完成正式模组发布验收。
- 决策依据：[本轮独立验证](../validation/0002-player-control-reproduction.md)、[可复跑探针](../../experiments/player-control/README.md)。原报告仍作为作者报告保留，不把缺失装置的旧数字追认为已复核。
- 替代或被替代的 ADR：无。

## 背景与约束

伙伴需要玩家身份、背包和生存规则，初期在 Minecraft Java 1.21.1 Fabric / Minecraft Forge 上运行。明确区分服务端直接创建的玩家实体、离线协议机器人、完成认证的正版账号客户端；这些身份不能互相冒充。本轮不使用真实账号、不调用付费模型、不承诺任意纯净服接入。

## 备选方案

| 方案 | 部署与身份 | 成本与限制 | 本轮证据 |
| --- | --- | --- | --- |
| A 服务端玩家实体 | 模组在拥有控制权的服务端直接构造玩家，不走账号登录 | 不需额外账号；要维护连接适配、tick、保存、死亡重生；缺少真正客户端回执 | 本仓库可复跑，Fabric/Forge 的 GameTestServer 与真正 IntegratedServer 共四组断言通过 |
| B 独立协议/完整客户端 | 用协议或游戏客户端连接服务器；需要在线身份时必须走合法认证 | 需维护协议、登录和客户端兼容；是否使用独立进程属于实现选择，不能假定每个伙伴必须一个进程 | PR #15 报告离线协议实验，但原装置缺失、未独立复现；真实账号认证未测 |
| C 同时维护 A 与 B | 对多种宿主提供适配 | 增加初期范围、账号及跨进程状态管理 | 不进入 MVP；以后有需求再立项 |

本轮选择 A。Forge 1.21.1 不提供早期版本的 FakePlayer 系统（[上游移除记录](https://github.com/MinecraftForge/MinecraftForge/commit/90dafb0df0651b52102e25f6a252554cde884878)），因此不依赖“Forge 已有现成假玩家”的假设。实验通过独立实现的无 socket 连接适配器完成，未复制参考模组实现。

## 已验证与未验证

通过固定 Java 21 / Gradle / 加载器版本的独立探针，四组运行均验证加入玩家列表、冲量移动、直接挖掘原语和掉落拾取、受伤、移除后重进保留 7 个原木、死亡掉落 7 个、手动适配重生、重生不复制物品及出站包丢弃。运行器检查全部断言、加载器和实际服务器类；集成服另外检查客户端完成标志。

这证明选用 A 具有可执行的基础路径。它不证明导航、正常耗时采集、正式聊天、第三方模组、账号认证或客户端回执已完成。GameTestServer 不是普通 DedicatedServer，不能以其 `dedicated` 标志代替真实部署类型；两侧集成服则由日志明确记录为 `net.minecraft.client.server.IntegratedServer`。

## 决定与执行边界

1. MVP 使用服务端玩家实体，归属、UUID、名字和存档均独立于真实用户。伙伴不是正版登录账号；不复用真实玩家身份。
2. 世界状态读取与动作执行服从服务端线程约束，权限、生存规则、距离、停止与数量都由执行端校验。模型和客户端只能提出意图。
3. Fabric/Forge 各有生命周期、事件及连接适配。实验的 `ProbeConnection` 只丢弃消息，不能直接作为已兼容所有模组的生产连接实现。
4. 初期推理与服务端同侧且异步执行，凭据仅保存在受信任的推理端。客户端承担展示和配置入口，不能接收或广播模型密钥；没有配置则保持 Mock，不发付费请求。真实实现由 #5 完成。
5. MVP 先按双端安装开发与验收；不承诺无模组客户端也能使用正式聊天/配置。以后需要客户端推理、无模组客户端或纯净服接入时新增 ADR。
6. 将探针结论接入 #4 的正式伙伴生命周期，再由 #8/#9/#10 实现合规动作与导航，不把实验接口调用当作可发布的干活能力。

## 安装矩阵与责任

| 场景 | 目标安装条件 | 世界执行 | 推理目标 | 目前证据 / 后续验收 |
| --- | --- | --- | --- | --- |
| Fabric 单机内置服务器 | 本机安装对应 Fabric 模组，一份游戏进程含逻辑两端 | 内置服务器线程 | 本机服务端侧异步 | 独立探针 IntegratedServer 通过；正式工程接入仍归 #2/#4/#11 |
| Forge 单机内置服务器 | 本机安装对应 Forge 模组 | 内置服务器线程 | 同上 | 同上 |
| Fabric / Forge 自建专服 | 服务端安装对应模组；MVP 客户端也安装对应模组 | 服务端线程 | 受信任服务端侧异步 | 两侧 GameTestServer 探针通过；普通专服安装、握手和端到端聊天归 #2/#6/#11 |
| 纯净服或不可安装模组的服务器 | A 路线不可由本模组在该服务器创建伙伴；B 需另行立项 | 由服务器按协议处理动作 | 另行设计 | 不在初期承诺范围；真实账号、服务端规则和兼容性未测 |

“目标安装条件”是本项目的开发与发布范围，不是所有组合都已通过的兼容声明。服务端实体的存在不要求它拥有真实客户端；双端安装要求指用户运行的正式模组与交互界面。

## 代价、后续与复审

- 生产连接需处理包生命周期、断线、区块跟踪、保存和重生；#4 实现并检验恢复与物品一致性。
- 资源包、GUI、自定义通道和其他客户端回执不能靠丢弃消息模拟。逐个兼容，由 #11 验证；登录事件被触发不代表第三方模组已兼容。
- 当前无自定义皮肤验证，不把默认档案外观说成永远无法扩展皮肤；后续需独立设计资源来源、授权与身份展示。
- #1 的基础可行性记录不替代普通 DedicatedServer 部署、多人隔离、长时间运行或正式发布四格矩阵。这些门槛继续保留在 #2/#4/#6/#11。
- 用户要求真实账号、纯净服、客户端推理，或出现无法修复的连接兼容问题时复审；不得默默改变身份解释、密钥位置或安装承诺。
