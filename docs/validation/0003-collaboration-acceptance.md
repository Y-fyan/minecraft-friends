## 四项实际使用反馈的处理

1. 认领后立即同时更新 Assignee、交付范围及唯一状态；阻塞/恢复采用状态切换，不能叠加矛盾标签。
2. 说明隐私邮箱常见格式、旧账号差异及 Settings → Emails 的准确来源。区分本地作者信息与推送后的 GitHub 关联核对，不把本地配置当关联证明。
3. 验证代码、固定依赖、构建/运行入口和关键断言随 PR 入库；报告记录源码提交。一次性装置也要可获取，不能只提交无法运行的命令；世界、凭据、缓存和完整私人日志不入库。
4. PR 增加可选 AI 辅助说明，要求对实际验证负责并保留真实作者；不要求给工具虚构人类署名。
