# M2 本机性能对照

先构建根正式 JAR 和本助手，再运行 `JAVA_HOME=/已有/JDK21 python3 experiments/m1-acceptance/run_performance.py`。串行运行六个独立客户端 JVM：Fabric/Forge 各自关闭功能、启用并等待、启用并实际跟随。不要同时运行其他本项目游戏验收，以免相互竞争资源。

每轮创建随机独立平坦世界，种子 4321，布置相同石板地图；地图准备后预热 160 tick，再从 `getTickTimesNanos` 读取前一个已完成 tick，收集 600 个原始样本计算最近秩 p50/p95/p99。活动组只移动测试主人作为目标，同伴不得传送且实际累计移动超过 12 格。关闭组检查功能确实关闭且仅一个真实玩家；空闲组创建同伴并等待。客户端连接、渲染和地图设置相同，使用软件渲染。

本机 Alpha 门槛为 p95 小于 50ms、p99 小于 100ms；50ms 对应 20 TPS 的单 tick 时长，100ms 允许少量短暂停顿。原始最大值也保留，不删 GC 或慢样本。这不是所有硬件的性能保证。进程内存记录整个集成客户端/服务端 JVM 的预热后与结束时已用堆、最大堆，不是模组独占内存，也不能证明长期无泄漏。

默认离线 mock，无 HTTP 凭据或远程请求，因此本轮远程调用、token 与服务费均为零；不能据此估计真实模型速度或价格。生产规划另有每主人 20 tick 冷却、最多 16 个 pending、模型共享最多 4 个在途调用、最长 30 秒超时；感知最多检查 245 个位置并保留 64 个非空方块、41 个背包槽。每 tick 处理最多 8 个主人、4 次寻路、2 次区域扫描；每次寻路最多 512 节点、半径 24。快照在显式规划时读取，不每 tick 调模型。

每轮沿用 `run_actions.py` 的源码、JAR、退出码及固定断言校验，临时配置在结束时还原。聚合 JSON 记录 CPU、内核、核数、全部六轮路径与指标；失败立即停止，保留失败证据，不以缺少指标的运行冒充成功。
